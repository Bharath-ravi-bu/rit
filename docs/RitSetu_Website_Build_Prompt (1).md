## 14. Technical implementation

### Workspace behavior

1. Inspect the existing workspace before creating files.
2. Preserve existing user work and follow repository instructions such as `AGENTS.md`.
3. If an existing compatible application exists, extend it cleanly.
4. If the workspace is empty, create a modern production-ready web application.

### Preferred stack for an empty workspace

- Current stable **Next.js** with App Router
- **TypeScript** with strict mode
- **Tailwind CSS**
- Accessible, reusable components
- Server components by default; client components only where interaction requires them
- Content stored in typed local configuration/data files so it can later connect to a CMS
- Minimal, carefully selected dependencies

If the environment strongly favors another supported React stack, use it only when it provides equivalent SEO, accessibility, performance, and routing capabilities. Document the decision.

### Code architecture

Create reusable components for:

- Header and mobile navigation
- Footer
- Buttons and links
- Section headings
- Service cards
- Product cards and status badges
- Process steps
- CTA bands
- Contact form
- SEO metadata
- Structured data
- Empty states and article cards

Keep business content separate from presentation components. Avoid one oversized page component.

### Quality requirements

- Fully responsive from 320px mobile width through large desktops
- Semantic HTML
- WCAG 2.2 AA-oriented implementation
- Complete keyboard navigation
- Visible focus indicators
- Appropriate ARIA only where semantic HTML is insufficient
- Optimized fonts and assets
- No layout shift from images or fonts
- No console errors
- No broken links
- Meaningful loading, error, empty, and success states
- Forms usable with keyboard and screen readers
- Lighthouse-oriented performance, accessibility, SEO, and best practices

### SEO and sharing

Implement:

- Unique title and description for every route
- Canonical URLs using `https://ritsetu.com`
- Sitemap
- `robots.txt`
- Open Graph metadata
- Social-sharing image generated from the RitSetu identity
- Organization structured data
- Service structured data where appropriate
- Meaningful heading hierarchy
- Clean URLs
- Favicons and web manifest

Suggested homepage title:

> RitSetu — AI Engineering, Legacy Modernization and Product Development

Suggested homepage description:

> RitSetu modernizes legacy applications, productionizes AI-generated software, integrates responsible AI, and builds secure, scalable digital products.

### Security and privacy

- Never commit secrets
- Provide `.env.example`
- Validate and sanitize form data
- Add sensible security headers
- Avoid unsafe HTML injection
- Do not add invasive tracking
- Keep analytics optional and environment-configured
- Do not show a cookie banner when no non-essential cookies are used
- Explain any third-party service introduced

### Testing

Add appropriate tests for:

- Navigation
- Primary CTA links
- Mobile menu
- Contact-form validation
- Key rendering paths
- Accessibility-sensitive interactive components

Use the project’s established test framework if present. For a new project, choose a small, maintainable testing setup.
